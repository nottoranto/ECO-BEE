# ECO BEE Phase 2 - แบบออกแบบระบบตาม Feedback ลงพื้นที่ครั้งที่ 1

## หลักการออกแบบ

- แปลง (`plots`) เป็นหน่วยหลัก และมีพืชหลายชนิด (`plot_crops`) อยู่ภายในแปลงเดียว
- ข้อมูลที่ผู้ใช้สำรวจจริงต้องเก็บวันที่ ผู้บันทึก และแหล่งที่มา
- ผลคำนวณทุกชนิดต้องแสดงเวอร์ชันแบบจำลอง ระดับความเชื่อมั่น และวันที่คำนวณ
- ระบบห้ามสร้างเปอร์เซ็นต์ผลผลิตหรือจำนวนรังจากข้อมูลที่ยังไม่มีงานวิจัยรองรับ
- รูปภาพและพิกัดละเอียดเป็นข้อมูลส่วนตัว เปิดเผยเฉพาะเมื่อเจ้าของอนุญาต

## 1. พืชหลายชนิดภายในแปลงเดียว

### โครงสร้างข้อมูล

- `plots`: `id`, `plot_code`, `owner_id`, `name`, `geometry`, `area_rai`, `visibility`, `created_at`
- `plot_crops`: `id`, `plot_id`, `plant_code`, `variety`, `tree_count`, `planted_at`, `spacing_m`, `source`, `created_at`
- `crop_observations`: `id`, `plot_crop_id`, `observed_at`, `growth_stage`, `bloom_status`, `bloom_percent`, `health_status`, `pesticide_use`, `note`, `photo_id`

### หน้าจอ

1. ผู้ใช้วาดขอบเขตแปลงเพียงครั้งเดียว
2. ระบบสร้างรหัส เช่น `PL-001`
3. ภายในหน้าแปลงมีปุ่ม “เพิ่มชนิดพืช” เพิ่มมะม่วง สับปะรด สตรอว์เบอร์รี ฯลฯ ได้หลายรายการ
4. แต่ละชนิดระบุพันธุ์ จำนวนต้น วันที่ปลูก และสถานะการออกดอกแยกกัน

## 2. จัดกลุ่มและแสดงจำนวนรังตามสายพันธุ์

### การแสดงผล

- ระดับซูมไกล: cluster แสดงจำนวนรังทั้งหมด และวงสีแบ่งสัดส่วนสายพันธุ์
- ระดับสวน: การ์ดสรุป `ชันโรง 12 | ผึ้งโพรง 4 | ผึ้งพันธุ์ 2 | ผึ้งหลวง 1`
- ระดับใกล้: หมุดแต่ละรังใช้สีประจำสายพันธุ์และรัศมีหาอาหารจริง
- ตัวกรองเลือกแสดงหลายสายพันธุ์พร้อมกันได้

### API

- `GET /api/hives/summary?bounds=...&group_by=species`
- ผลลัพธ์มี `species`, `count`, `public_count`, `private_count`, `centroid`

## 3. กรองพืชที่เหมาะกับผึ้งแต่ละสายพันธุ์

เพิ่มตาราง `bee_plant_suitability`:

- `bee_species`, `plant_code`, `suitability_score` (0-100)
- `resource_match` (น้ำหวาน/เกสร/ทั้งสอง)
- `evidence_level` (`unverified`, `observational`, `research_supported`)
- `source_title`, `source_url`, `notes`

สูตรเริ่มต้นใช้เฉพาะข้อมูลทรัพยากรอาหาร ช่วงออกดอก ขนาด/ลักษณะดอก และหลักฐานการเข้าเยี่ยมดอก ถ้าไม่มีข้อมูลให้แสดง “ยังประเมินไม่ได้” แทนคะแนน 0

## 4. บันทึกการเพาะปลูกและการเติบโตรายแปลง

หน้า Timeline ของแปลงประกอบด้วย:

- ปลูก/ย้ายปลูก
- ใส่ปุ๋ย ให้น้ำ ตัดแต่ง
- เริ่มออกดอก ออกดอกสูงสุด ดอกโรย
- ใช้สารเคมี พร้อมช่วงงดนำรังเข้า
- โรค/แมลง ความเสียหาย และหมายเหตุ
- ภาพถ่ายก่อน-หลัง

API: `GET|POST /api/plots/{plot_id}/events` และแก้ไข/ลบได้เฉพาะเจ้าของหรือหน่วยงานที่ได้รับสิทธิ์

## 5. ประเมินจำนวนต้นจากภาพถ่าย/แผนที่

ออกแบบเป็นงานประเมิน (`tree_count_jobs`) ไม่เขียนทับค่าที่เกษตรกรยืนยัน:

1. ผู้ใช้อัปโหลดภาพโดรน/ภาพถ่าย หรือเลือกภาพแผนที่ของแปลง
2. ระบบตรวจคุณภาพภาพ ความละเอียด พื้นที่ และข้อมูลพิกัด
3. โมเดลตรวจจับเรือนยอด/ตำแหน่งต้นไม้ สร้างจุดบนแผนที่
4. แสดงจำนวนประมาณ ช่วงความคลาดเคลื่อน และ confidence
5. ผู้ใช้เพิ่ม/ลบจุดและกด “ยืนยันจำนวนต้น”

เก็บ `estimated_count`, `confirmed_count`, `model_version`, `confidence`, `reviewed_by`, `reviewed_at` แยกกันเสมอ สำหรับ MVP ให้ใช้การวางจุดกึ่งอัตโนมัติก่อน แล้วค่อยฝึกโมเดลจากภาพที่ได้รับอนุญาต

## 6. ระดับความเสี่ยงแดง-ส้ม-เหลือง-เขียว

คะแนน 0-100 คำนวณจากองค์ประกอบที่อธิบายได้:

- 40% ระยะห่างจากพื้นที่ใช้สารเคมี
- 25% ความใหม่และชนิดสารเคมี/ช่วงปลอดสาร
- 15% ช่องว่างอาหารในปฏิทิน 12 เดือน
- 10% ความหนาแน่นรังเทียบทรัพยากรอาหาร
- 10% สภาพอากาศรุนแรงหรือการแจ้งเตือนพื้นที่

ระดับ: เขียว `0-24`, เหลือง `25-49`, ส้ม `50-74`, แดง `75-100` แต่ต้องให้หน่วยงานปรับ threshold ได้ ระบบแสดงเหตุผล 3 อันดับแรก ข้อมูลที่ขาด และเวลาประเมิน ห้ามแสดงเพียงสีโดยไม่มีคำอธิบาย

## 7. ประเมินเปอร์เซ็นต์ผลจากการผสมเกสร

ใช้ตาราง `pollination_models` แยกตามพืชและบริบท:

- ชนิดพืช สายพันธุ์ผึ้ง วิธีปลูก (กลางแจ้ง/โรงเรือน)
- ค่า baseline และค่าที่มีผึ้ง พร้อมหน่วยชัดเจน เช่น fruit set, yield, quality
- ขนาดตัวอย่าง พื้นที่ศึกษา ช่วงความเชื่อมั่น และแหล่งอ้างอิง
- เวอร์ชันและสถานะการรับรองโดยผู้เชี่ยวชาญ

ผลลัพธ์ต้องใช้ข้อความ “คาดการณ์” และแสดงเป็นช่วง เช่น `เพิ่มขึ้นประมาณ 15-25%` ไม่แสดงค่าจุดเดียวเมื่อหลักฐานไม่เพียงพอ หากไม่มีโมเดลตรงชนิดพืชและบริบท ให้ตอบว่า “ยังไม่มีหลักฐานเพียงพอ”

## 8. ข้อมูลการฟื้นฟูระบบนิเวศ

เพิ่มคลัง `restoration_evidence` และแผนฟื้นฟูรายพื้นที่ (`restoration_plans`):

- เป้าหมาย: ความต่อเนื่องของอาหาร ความหลากหลายพืช หรือทางเชื่อมถิ่นอาศัย
- พืชท้องถิ่นที่แนะนำ เดือนออกดอก สภาพดิน/น้ำ และความเหมาะสมพื้นที่
- baseline, ตัวชี้วัด, เป้าหมาย, รอบติดตาม และภาพก่อน-หลัง
- งานวิจัย/DOI/URL ผู้ตรวจทาน และระดับหลักฐาน

Dashboard เปรียบเทียบก่อน-หลัง เช่น จำนวนชนิดพืช เดือนที่มีอาหารครบ และอัตราการพบผึ้ง โดยไม่อ้างผลเชิงเหตุและผลเกินหลักฐาน

## 9. น้ำผึ้งหนึ่ง Lot จากหลายฟาร์ม

ปรับจาก `harvest_batches -> hive_id` เป็นโครงสร้าง:

- `product_lots`: รหัส Lot ผลิตภัณฑ์ ปริมาณรวม วันที่ผลิต ผู้รับผิดชอบ สถานะ
- `lot_sources`: `lot_id`, `harvest_batch_id`, `quantity_kg`, `percentage`, `farm_id`, `hive_id`
- `lot_events`: รับเข้า ผสม บรรจุ ตรวจคุณภาพ ขนส่ง และเรียกคืน
- `lot_quality_tests`: ความชื้น Brix สารตกค้าง ห้องปฏิบัติการ เอกสารผลทดสอบ

กฎสำคัญ: ผลรวม `quantity_kg` ของแหล่งที่มาต้องเท่าปริมาณ Lot ภายในค่าคลาดเคลื่อนที่กำหนด และต้องตรวจย้อนกลับจาก QR ไปยังทุกฟาร์มย่อยได้ตามระดับสิทธิ์ ข้อมูลพิกัดและเบอร์โทรไม่แสดงสาธารณะ

## API และสิทธิ์หลัก

- Farmer: จัดการแปลง พืช เหตุการณ์ ภาพ และรังของตนเอง
- Organization: ตรวจสอบ/รับรองข้อมูล ดูภาพรวมเครือข่าย และสร้าง Lot รวมเมื่อได้รับสิทธิ์
- Consumer: อ่านเฉพาะข้อมูล Traceability ที่อนุญาตผ่าน QR
- Research reviewer: อนุมัติแบบจำลอง งานวิจัย และเวอร์ชันสูตรคำนวณ

ทุก mutation บันทึก `audit_logs` พร้อม actor, เวลา, ค่าเดิม และค่าใหม่

## ลำดับการพัฒนา

### Phase 2A - โครงสร้างภาคสนาม

1. สร้าง `plots`, `plot_crops`, `crop_observations`
2. ย้ายข้อมูล `plants` เดิมโดยไม่ลบข้อมูลต้นทาง
3. เพิ่มหน้ารายละเอียดแปลงและ Timeline
4. เพิ่ม cluster/ตัวกรองรังตามสายพันธุ์

### Phase 2B - การวิเคราะห์

1. เพิ่ม suitability พร้อมแหล่งอ้างอิง
2. เพิ่ม risk score แบบอธิบายได้
3. เพิ่ม pollination model registry
4. เพิ่ม restoration plan และตัวชี้วัดก่อน-หลัง

### Phase 2C - ภาพและห่วงโซ่ผลิตภัณฑ์

1. ระบบอัปโหลดภาพและประเมินจำนวนต้นแบบ human-in-the-loop
2. Lot จากหลายฟาร์มและการตรวจสอบยอดปริมาณ
3. QR ใหม่และ workflow เรียกคืนสินค้า

## เกณฑ์รับงาน

- แปลงหนึ่งมีพืชอย่างน้อย 3 ชนิดและประวัติแยกกันได้
- ย้ายข้อมูลเดิมครบและย้อนกลับได้
- สี/จำนวนรังตรงกับข้อมูลฐานข้อมูลทุกระดับซูม
- คะแนนทุกชนิดระบุสูตร เวอร์ชัน แหล่งข้อมูล และ confidence
- ผู้ใช้แก้ผลนับต้นจากภาพก่อนยืนยันได้
- Lot หลายฟาร์มปฏิเสธเมื่อยอดปริมาณไม่สมดุล
- QR ไม่เปิดเผยพิกัดละเอียดหรือข้อมูลส่วนตัว
- ผ่าน unit, integration, migration rollback และ end-to-end tests
